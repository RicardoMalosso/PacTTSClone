## Deterministic suites

```
python -m pip install -e '.[dev,browser]'
python -m pytest -q
python -m ruff check .
python -m playwright install chromium
python -m pytest tests/browser --browser chromium -q
```

Core tests include real FFmpeg decoding/encoding, SQLite persistence, startup
recovery, bounds/validation, configuration, saved voices/transcripts/thumbnails,
moderation-before-render, custom terms/Unicode/cooldowns, native-hotkey message-loop
simulation, IRC framing/PING/reconnect/deduplication, FIFO/countdown/cancel/replay,
coordinator/mirror leases and per-stage logs. An actual spawned fake-engine worker
is killed mid-generation, then a new process successfully completes another job.
This proves process lifecycle/cancellation, not real voice quality or GPU behavior.

Browser tests use actual Chromium with explicit fake inference engines: original
upload/player/download flow; saved voices, transcription and settings; timer and
cancel controls; channel configuration/moderation/countdown/replay; locale detection
and override across tabs/reloads; speech-language persistence; existing channel
command dropdown refresh after voice preparation without losing drafts; sharing controls; remote admin/OBS cookie bootstrap; backend panic
stopping browser audio. Public-origin tests emulate cloudflared forwarding in the
browser and enforce actual server capability checks; they do not claim an external
internet tunnel was established. Keep in-flight browser routes drained during
teardown so a context closure does not poison the next test.

Every deterministic test has a 60 s timeout; CI core has a 15 s per-test and 3 min
step timeout. Never use large binary values as autogenerated parameter IDs. The
20 MiB fixture has the explicit ID over-20MiB. CI tests Windows/Linux Python
3.11/3.12 and Chromium on Linux, plus wheel build and PowerShell syntax on Windows.

## Real model

Install matching PyTorch and `.[inference]`. Example:

```
pacttsclone-smoke --device cpu --reference reference.mp3 --ref-text "Exact reference transcript." --text "Olá, bom dia."
```

The smoke now uses the production spawned worker. A separate preset smoke creates
a voice with blank transcript, waits for real local ASR, then generates from the
saved voice and verifies that the speech job has no second transcribe stage.
Record hardware/thread count, phase wall/CPU time, RAM, model and outcome; inspect
MP3 format with FFprobe. Perceptual quality and performance on the user's hardware
require separate listening/benchmarking, not assertions against a fake model.

## RC4 remote access and observability

without polling owner-only setup/tunnel endpoints. Shared OBS links include a
channel capability and work in a separate browser context. A lost cookie gets one
bootstrap retry; revoked/unauthorized links stop polling and ask for a fresh link.

base-model resident state; changing voice repeats reference conditioning rather

[remote observability design](remote-observability-design.md).

## Reference transcription regression — 2026-10-24

The packaged minimal FFmpeg omitted the f32le muxer and pcm_f32le encoder used
by Transformers ffmpeg_read. Enable both and execute that exact pipe protocol
against the newly compiled Windows binary in the installer build. ASR receives
already decoded float32 PCM through OmniVoice's tuple API, avoiding a second
FFmpeg decode. A regression uses real MP3/WAV decoding, verifies every PCM sample
and rate, blocks subprocess creation during transcription, and checks lazy ASR
reuse; the model is mocked, not real inference.

Local checks: 136 backend tests passed (tests/test_default_voices.py excluded
because binary preset assets are unavailable in this connector checkout); all
22 focused engine/audio tests passed; ruff and bash syntax checks passed. The new
regression fails when the old path-based model call is restored. Initial broad
run failed because the partial checkout lacked static files; after retrieving
those files and installing local metadata the above backend run passed.
Windows compiled-binary smoke awaits GitHub Actions. No real Whisper/OmniVoice
weights or physical GPU inference were executed locally; these results do not
establish speech quality or end-to-end model inference.

## GitHub Actions execution policy

- `Tests` starts on pull requests, pushes to `main`, or manual dispatch.
  Only `main` pushes trigger push-based jobs, avoiding duplicate push/PR
  executions for feature branches.
- The `fast` job checks Ruff, Python compilation and YAML syntax before expensive
  Windows FFmpeg setup or browser/core tests. Chromium runs after this gate;
  Windows/Linux Python 3.11/3.12 tests also wait for the Windows FFmpeg artifact.
  The matrix uses `fail-fast: false` to retain cross-platform diagnostics.
- Superseded test runs are cancelled within their workflow/ref concurrency group.
  GitHub retains their run history; the intermediate FFmpeg artifact expires in
  7 days.
- `Windows installer preview` is explicitly dispatched from GitHub Actions.
  It reruns the reusable full test suite and only builds/acceptance-tests the
  installer if every check succeeds. Manual builds are not cancelled.
- Installers are attached to GitHub Actions for 14 days, diagnostics for 7.
  Publication requires the explicit `publish_draft` checkbox and execution from
  `main`. Existing draft or published releases are never deleted or overwritten.
  The verified installer/test procedure is otherwise unchanged.
